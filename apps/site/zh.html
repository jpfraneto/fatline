你自己的 Farcaster 节点，你自己的客户端。

不需要任何人的 API 密钥。Farcaster 或 Hypersnap，由你选择，两者平等。

开始之前

  • 电脑上需要 git、Node.js 22.12 或更新版本和 ssh。
  • 一个绑定银行卡的 Hetzner Cloud 账户，并把 API 令牌保存在 ~/.hetzner-token（chmod 600）。
  • 新的 Hetzner 账户有额度限制（我们的是：卷总共 1,385 GB，14 个 vCPU）。一个节点需要 700 GB 的卷，所以一个新账户只够一个完整节点。Farcaster 和 Hypersnap 两个节点并排运行，需要两台服务器和两个卷。
  • 发帖需要你 Farcaster 账户的助记词，只在你自己的终端里输入。
git clone https://github.com/jpfraneto/infinicaster && cd infinicaster

./infinicaster compute            # (0) 租一台能装下节点的机器：先报价，你输入 "create" 才会创建
./infinicaster node farcaster     # (1) 在上面装你的读取节点，不需要 API 密钥（或：node hypersnap）
./infinicaster client             # (2) 你的客户端，从你的节点读取，在 http://localhost:8787

尚未完整测试 每一步都单独运行过。从零开始、一口气跑完三条命令的完整流程还没有做过。我们自己的节点是用更早的一步式版本搭建的。

你在 Farcaster 上是谁

FID。你的 Farcaster ID 是一个数字，例如 18350，登记在 Optimism 上的一个合约（ID 注册表）里。用户名、帖子和关注关系都挂在这个数字上。
托管地址。拥有你 FID 的以太坊地址。它的助记词是账户的主钥匙：可以添加和移除密钥、转移 FID。它从不签日常的帖子。
应用密钥。日常的帖子由应用密钥（Ed25519 密钥，也叫 signer）签名。你用的每个应用（例如 Warpcast 或 Firefly）都有自己的密钥，由你的托管地址授权。授权记录里写着这个应用自己的 FID，所以本客户端能告诉你每条帖子是哪个应用发的。
消息。一条 cast、一个赞、一次关注、一次资料修改，都是一条签名消息：数据、它的哈希、签名，以及签名用的密钥。任何节点都可以自行验证，不需要问任何人。

第 0 步：给节点一台机器

./infinicaster compute --quote   # 只看价格，不创建任何东西
./infinicaster compute           # 要求你输入 "create"

它会选有货的、内存至少 16 GB 的最便宜机型（2026-10-22 是 cax31，8 个 ARM CPU），加一个 700 GB 的卷，先显示价格再询问。它只负责租机器，第 1 步再装节点。创建的一切都记录在 .infinicaster/hetzner.json，可以精确删除。

为什么要租？一个 Farcaster 节点保存所有账户当前的消息，今天大约 600 GB。大多数笔记本没有这么多空闲磁盘。

已经有一台装了 Docker、16 GB 内存、约 700 GB 空闲磁盘的机器？跳过这一步，在那台机器上用 ./infinicaster node farcaster --local。

第 1 步：你的读取节点

./infinicaster node farcaster    # 或：./infinicaster node hypersnap

它在第 0 步的机器上安装该网络的节点，并跟踪初始快照的传输（约 400 GB，大约 1 到 3 小时）。节点在 /v1/info 上应答后，就会成为 infinicaster.config.json 里你自己的节点，第 2 步就从它读取。一台服务器只放一个网络。

读取节点和验证者。Snapchain 是 Farcaster 的网络软件，有一小组验证者对消息的顺序（区块）达成一致。你的节点是读取节点：跟随这些区块，保存每条消息的副本。你发帖时，节点检查消息并转发给验证者。读取从不需要验证者的许可。
Farcaster 或 Hypersnap。Hypersnap 是 Snapchain 的社区分支。两者使用相同的 API，接受相同的签名消息。Hypersnap 保留完整历史；Farcaster 按每个账户的存储上限删除旧消息。默认没有偏向哪一个：由你选择。

初始快照：新节点从网络快照开始，而不是重放多年的区块。在租来的服务器上，快照被流式写入磁盘，三个分片同时进行：压缩后约 400 GB，共 5,695 块，解压后约 600 GB。磁盘上只保留一份。节点默认只保留一天的区块。

下载和追上网络需要多久：尚未测量。

健康意味着同步，而不只是"在运行"。节点健康的标准是 /v1/info 显示每个分片的 blockDelay 都很小。端口开着不算。

第 2 步：你的客户端

./infinicaster client

它会安装、构建并在 http://localhost:8787 启动客户端。页面顶部总会写明正在从哪个节点读取。在设置里选择网络和节点：

  • 指定一个节点：所有读取和发帖只经过这个节点。它宕机时，你会看到写明节点名的错误。客户端绝不会背着你切换。
  • 自动：按列表顺序使用第一个应答的节点，并说明正在用哪一个；如果换了，会告诉你。

发帖：客户端自己的应用密钥

./infinicaster identity --fid <你的 FID> --dry-run   # 检查一切，不注册
./infinicaster identity --fid <你的 FID>             # 注册本客户端的密钥

在你自己的终端运行。助记词在隐藏输入框中输入，密钥注册后立即遗忘，从不保存。不需要交易，不需要 gas。这个密钥只能发帖、互动、关注和修改资料。

存储租金和服务器账单是两回事。存储租金在链上按账户支付，决定网络为你保留多少消息，不支付任何服务器。节点服务器是另一笔账单，付给托管它的人。
