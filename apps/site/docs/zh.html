你自己的 Farcaster 节点，你自己的客户端。

Fatline 是两样东西。一个 Farcaster 客户端：读取 Snapchain 或 Hypersnap，两者之间有一个开关，并且总会写明它从哪个节点读取。还有 Base 上的一个 USDC launchpad：每个币的手续费支付一台服务器，让它多运行一份完整的 Farcaster 副本。

不需要任何人的 API 密钥。你的 agent 做事；每一笔付款都由你在自己的钱包里批准。原名 Infinicaster。

开始之前

  • 电脑上需要 git、Node.js 22.12 或更新版本和 ssh。
  • 一个在 Base 上有约 12 USDC 的钱包。不需要银行卡、账户或 ETH：服务器用签名付款（x402）。你在自己的钱包里批准付款：用手机钱包扫二维码，或在浏览器钱包里批准。如果你更想用自己的 Hetzner 账户（银行卡，按小时计费）：fatline compute hetzner。
  • 新的 Hetzner 账户有额度限制（我们的是：卷总共 1,385 GB，14 个 vCPU）。一个节点需要 700 GB 的卷，所以一个新账户大约每个卷只够一个完整节点。我们在一台服务器（8 个 Arm 核心，16 GB）上用两个卷同时运行两个网络，正好在这个额度上：Hypersnap 最小的分片（44 GB）放在服务器自带的磁盘上。两个网络合计每月 131.82 美元。
  • 发帖需要你 Farcaster 账户的助记词，只在你自己的终端里输入。

最简单的方式：curl -fsSL https://fatline.ink/install.sh | sh 会把 Fatline 下载到 ~/fatline 并启动 fatline setup：逐步引导，每一步之前说明它做什么、花多少钱、要多久，然后问你：继续、跳过或停止。再运行一次就从停下的地方继续。
用 AI 助手：把这句话发给 Claude Code、Codex 或任何能运行命令的助手：Help me run a Fatline: https://fatline.ink/skill.md。它会先给你看价格并等你同意，绝不碰你的助记词或令牌。

git clone https://github.com/jpfraneto/fatline && cd fatline
npm install -g .             # the fatline command, from anywhere

fatline compute            # (0) 用 USDC 租一台能装下节点的机器：先报价，你输入 "pay" 才会付款
fatline node snapchain     # (1) 在上面装你的读取节点，不需要 API 密钥（或：node hypersnap）
fatline client             # (2) 你的客户端，从你的节点读取，在 http://localhost:8787

已完整跑通 三条命令已从零开始完整跑通，也有其他人在自己的服务器上跑过：@jmsaulnier、@jvaleska.eth。

放不下一个节点？fatline follow 只从你选的一个节点复制你选的账户。它不是节点。

你在 Farcaster 上是谁

FID。你的 Farcaster ID 是一个数字，例如 18350，登记在 Optimism 上的一个合约（ID 注册表）里。用户名、帖子和关注关系都挂在这个数字上。
托管地址。拥有你 FID 的以太坊地址。它的助记词是账户的主钥匙：可以添加和移除密钥、转移 FID。它从不签日常的帖子。
应用密钥。日常的帖子由应用密钥（Ed25519 密钥，也叫 signer）签名。你用的每个应用（例如 Warpcast 或 Firefly）都有自己的密钥，由你的托管地址授权。授权记录里写着这个应用自己的 FID，所以本客户端能告诉你每条帖子是哪个应用发的。
消息。一条 cast、一个赞、一次关注、一次资料修改，都是一条签名消息：数据、它的哈希、签名，以及签名用的密钥。任何节点都可以自行验证，不需要问任何人。

第 0 步：给节点一台机器

fatline compute --quote   # 只看价格，不创建任何东西
fatline compute           # 要求你输入 "pay"

它在 AgentMetal 租一台服务器（4 CPU，8 GB 内存）一天，并加一个 700 GB 的磁盘：约 11 USDC，从你的钱包用 Base 上的 USDC 签两次名付款（x402）。预付，一天结束后自动停止；--days N 买更多天。它只负责租机器，第 1 步再装节点。想用自己的 Hetzner 账户：fatline compute hetzner。

为什么要租？一个 Farcaster 节点保存所有账户当前的消息，今天大约 600 GB。大多数笔记本没有这么多空闲磁盘。

已经有一台装了 Docker、16 GB 内存、约 700 GB 空闲磁盘的机器？跳过这一步，在那台机器上用 fatline node snapchain --local。

第 1 步：你的读取节点

fatline node snapchain    # 或：fatline node hypersnap

它在第 0 步的机器上安装该网络的节点，并跟踪初始快照的传输（约 400 GB，大约 1 到 3 小时）。节点在 /v1/info 上应答后，就会成为 fatline.config.json 里你自己的节点，第 2 步就从它读取。一台服务器只放一个网络。

读取节点和验证者。Snapchain 是 Farcaster 的网络软件，有一小组验证者对消息的顺序（区块）达成一致。你的节点是读取节点：跟随这些区块，保存每条消息的副本。你发帖时，节点检查消息并转发给验证者。读取从不需要验证者的许可。
Farcaster 或 Hypersnap。Hypersnap 是 Snapchain 的社区分支。两者使用相同的 API，接受相同的签名消息。Hypersnap 保留完整历史；Farcaster 按每个账户的存储上限删除旧消息。默认没有偏向哪一个：由你选择。

初始快照：新节点从网络快照开始，而不是重放多年的区块。在租来的服务器上，快照被流式写入磁盘，三个分片同时进行：压缩后约 400 GB，分成 5,695 段下载，解压后约 600 GB。磁盘上只保留一份。节点默认只保留一天的区块。

我们的两个节点（2026-10-22 测量）：快照完成后，节点在仍落后 7 万到 10 万个区块时就开始应答，追赶速度约每分钟 270 个区块。Farcaster：06:42 UTC 开始应答，12:25 UTC 完全同步，用时 5 小时 43 分。之后重启服务器：47 秒后重新应答，62 秒后恢复同步。Hypersnap：10:21 UTC 开始应答，随后停滞了五个半小时：Hypersnap 仓库中的验证者列表缺少 Farcaster 于 2026-10-22 生效的验证者变更（issue #41）。我们的安装脚本现在改用 Snapchain 的列表，节点已恢复追赶。完全同步所需时间：尚未测量。

为什么没有轻节点。轻节点会从另一个节点复制当前状态，而不是从快照开始。目前 Snapchain 和 Hypersnap 的复制器都拒绝添加和移除应用密钥的消息，所以副本无法跟踪哪些密钥属于哪个账户。而且完整副本仍有约 300–400 GB。如果太大，请看只复制你关注的账户。

健康意味着同步，而不只是"在运行"。节点健康的标准是 /v1/info 显示每个分片的 blockDelay 都很小。端口开着不算。

第 2 步：你的客户端

fatline client

它会安装、构建并在 http://localhost:8787 启动客户端。页面顶部总会写明正在从哪个节点读取。在设置里选择网络和节点：

  • 指定一个节点：所有读取和发帖只经过这个节点。它宕机时，你会看到写明节点名的错误。客户端绝不会背着你切换。
  • 自动：按列表顺序使用第一个应答的节点，并说明正在用哪一个；如果换了，会告诉你。

放不下节点：只复制你关注的账户

fatline follow 18350 @dwr --network farcaster --node crackle --once
fatline follow 18350 --following --network hypersnap --node haatz   # 持续跟随；Ctrl+C 停止，再次运行会接着继续
fatline follow 18350 --followers --once                              # 加上关注他们的所有人（--depth 2：再加一层）
fatline feed --limit 20                                              # 只从本地副本读取时间线：不需要节点、网络或密钥
fatline follow list

它从你选的一个节点（Farcaster 或 Hypersnap，你自己的或公共的）复制你指定的账户（加 --following 时，还包括他们关注的所有人）到客户端的存档里。在客户端打开 #/archive/<fid> 即可阅读。只读取这一个节点，绝不切换。

这不是节点。每次运行都会这样说明。它信任那个节点：自己不检查消息签名或密钥。它不加入网络，也不帮助网络。它的完整和及时程度取决于那个节点：节点落后，它也落后。

发帖：客户端自己的应用密钥

fatline identity --fid <你的 FID> --dry-run   # 检查一切，不注册
fatline identity --fid <你的 FID>             # 注册本客户端的密钥

在你自己的终端运行。助记词在隐藏输入框中输入，密钥注册后立即遗忘，从不保存。不需要交易，不需要 gas。这个密钥只能发帖、互动、关注和修改资料。

存储租金和服务器账单是两回事。存储租金在链上按账户支付，决定网络为你保留多少消息，不支付任何服务器。节点服务器是另一笔账单，付给托管它的人。

已测试 2026-10-24 用真实账户（@anky，FID 18350）测试：注册密钥，然后发帖、回复、点赞、转发、关注，每一项都在我们的节点上确认，并在 crackle 上看到。

为什么叫 Fatline

我们所说的 fatline，是一条两端都握在你手里的线：一端是你的密钥在签名，另一端是你自己的节点在倾听，中间没有人把这条线租给你、再把它收回。让一条线保持畅通需要花钱，所以这条线自带钱袋：这就是 launchpad：每个蛋或 Fatliner 可以在 Clanker 上发行一个与 USDC 配对的币（最多 777 个，代号 = 它的姓氏），100% 的创作者手续费进入它自己的金库；任何人都可以调用 payCompute()，由金库向服务器的维护者付款，每期不超过约定费率。这个词来自 Dan Simmons 的小说《海伯利安》（Hyperion），但它在这里的含义是我们自己的。

合约已在 Base 上线并在 Basescan 验证；完整流程在 Base 的副本上用真实的 Clanker 演练过。尚未用真钱发行任何币（$FATLINE 第一个）。没有外部审计。

孵化一个 Fatliner：你的节点为一枚蛋保温

任何 Farcaster 账户都可以领取一枚蛋（每个账户一次，蛋会上链、不能转让）。只有 777 枚能孵化，没有人挑选。孵化时，同一个 token 变成 Fatliner，并从它的 DNA 读出一个姓氏：那就是它的币的 ticker（每个 Fatliner 一个币，$FATLINE 第一个）。你的节点为一枚蛋保温；连续三个“温暖的日子”，它就会孵化。铸造免费。

fatline hatchery install   # 在你的节点旁边装一个小服务，有它自己的密钥
fatline egg lay            # 用你的 app key 签名这枚蛋：这台服务器，这个地址
fatline egg                # 每天的温度
fatline hatch              # 三个温暖的日子之后：孵化给你，由服务器支付 gas

已经孵化的服务器（attesters）每小时检查你的服务器：节点有回应、已同步、能返回他们随机挑选的消息、hatchery 用蛋里写的密钥回应。24 次检查中通过 18 次就是温暖的一天；冷的一天不会重置。孵化后，你的服务器也成为 attester。合约在 Base 上：Fatliners（它也是 launchpad，一个合约，已在 Basescan 验证）。每次出售 Fatliner，8% 付给 Fatline 的建造者（royaltyTo）。第一个蛋已在 Base 上孵化：Thaituma（#13505）。
